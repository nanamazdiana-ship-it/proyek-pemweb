# Log Penggunaan AI (AI Usage Log) - Pertemuan 5

Dokumen ini mencatat riwayat pemanfaatan *Artificial Intelligence* (AI) selama pengerjaan praktikum Pemrograman Web (DOM Manipulation, Event Handling, Safe Rendering, & Web Storage) untuk transparansi dan dokumentasi teknis.

| Tanggal | Tujuan Penggunaan AI | Prompt Ringkas | Hasil / Solusi AI | Verifikasi & Keputusan Mahasiswa |
| :--- | :--- | :--- | :--- | :--- |
| 29/09/2026 | Memahami penerapan Safe DOM Rendering tanpa kerentanan XSS | "Bagaimana cara render kartu katalog dinamis tanpa memakai innerHTML?" | Memberikan pola render aman menggunakan `document.createElement()`, `textContent`, dan pembersihan container via `replaceChildren()`. | Diterapkan; fungsi `renderKatalog()` / `renderItems()` dibangun murni dengan manipulasi node DOM yang aman dari XSS. |
| 29/09/2026 | Menerapkan efisiensi penanganan event klik pada elemen dinamis | "Bagaimana cara buat tombol detail pada kartu yang dirender dinamis agar tetap bisa diklik?" | Mengarahkan penggunaan konsep *Event Delegation* dengan memasang listener pada container induk (`#daftar-alat`) dan mendeteksi target via `e.target.closest('[data-detail]')`. | Diterapkan dan berhasil diverifikasi; tombol detail merespons klik dan menampilkan informasi unit via alert modal. |
| 29/09/2026 | Memahami alur kerja Web Storage untuk data non-sensitif | "Gimana cara simpan preferensi tema dan memulihkannya saat di-reload?" | Memberikan sintaks `localStorage.setItem('theme', ...)` dan pembacaan awal saat pemuatan halaman `localStorage.getItem('theme')`. | Diterapkan; preferensi tema visual tersimpan di browser dan berhasil dipulihkan secara otomatis saat halaman di-refresh. |
| 29/09/2026 | Memahami alur data pengiriman formulir pada tingkat front-end | "Pesan pengajuan sewa ini perginya kemana kalau belum ada database?" | Menjelaskan alur penanganan event `submit` pada JavaScript untuk menangkap input, mencegah reload bawaan via `preventDefault()`, serta menampilkan *Form Feedback* instan. | Dipahami; alur penanganan form dijadikan bahan argumen pada refleksi dan laporan praktikum. |
| 06/10/2026 | Meningkatkan aksesibilitas dan validasi formulir minat sewa | "Jika salah memasukkan input, fokus harus menuju bagian yang salah; unit terisi juga harus ditolak." | Membantu menambahkan pesan error per kolom, fokus ke error pertama, validasi karakter nama/nomor, penolakan unit terisi, dan panduan skenario pemeriksaan. | Perubahan kode ditinjau pada tingkat implementasi; skenario browser dan peer review masih perlu dilakukan dan dicatat langsung oleh mahasiswa/reviewer. |
